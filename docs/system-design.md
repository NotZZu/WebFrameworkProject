**시스템 설계서**

자동화 검증시스템 서비스 개선 및 확장 기능 개발

*(Selenium 기반 웹 서비스 테스트 자동화 프레임워크 구축 중심 프로토타입)*

1\. 문서 개요

1.1 목적

본 문서는 「자동화 검증시스템 서비스 개선 및 확장 기능 개발」 프로젝트의 분석 단계에서 확정된 요구사항 정의서(FR-01~FR-15, NFR)를 기반으로, 설계 단계(3~5주)의 핵심 산출물인 시스템 설계서를 정의한다. 축소된 웹 서비스 프로토타입의 화면 구성, 데이터베이스 구조, API 설계를 다루며, 이후 구현 단계(6~10주)의 직접적인 개발 기준이 된다.

1.2 범위

본 문서는 요구사항 정의서의 4.1절(웹 서비스 기능 요구사항, FR-01~FR-06)에 대응하는 화면·데이터·API 설계를 다룬다. Selenium 테스트 자동화 프레임워크(FR-10~FR-15)의 아키텍처 설계는 별도 문서인 「테스트 자동화 아키텍처 설계서」에서 다룬다.

2\. 시스템 아키텍처

2.1 아키텍처 개요

본 프로토타입은 1인 개발 및 15주 일정에 맞춰 배포·운영 복잡도를 최소화한 단일 서버 3계층(3-tier) 구조로 설계한다.

- 프레젠테이션 계층: 서버 사이드 렌더링 템플릿(HTML/CSS/JS) — 사용자 유형별 화면 제공

- 애플리케이션 계층: Flask 기반 라우트/서비스 로직 — 인증, 가명·익명 처리, CAVP 신청 처리, 검증서 조회/위변조 판정

- 데이터 계층: SQLite(또는 SQLAlchemy 호환 RDB) — 사용자, 가명정보, 신청, 검증서 테이블

*테스트 자동화 프레임워크(Selenium/POM)는 애플리케이션과 분리된 별도 테스트 프로젝트로 구성하여, 웹 서비스를 블랙박스로 호출·검증한다.*

2.2 기술 스택

| **구분**      | **기술**                       | **비고**                                |
|---------------|--------------------------------|-----------------------------------------|
| 백엔드        | Python 3.x + Flask             | 경량 프레임워크, 라우팅/템플릿 렌더링   |
| 프런트엔드    | Jinja2 템플릿 + Bootstrap 5    | 반응형 레이아웃(PC 기준), 최소 스타일링 |
| 데이터베이스  | SQLite (SQLAlchemy ORM)        | 단일 파일 DB, 시연 환경에 적합          |
| 인증          | 세션 기반 로그인 (Flask-Login) | 개인/기업/기관 유형 구분 저장           |
| 테스트 자동화 | Selenium WebDriver + Pytest    | POM 구조, 별도 리포지토리/폴더로 분리   |
| 버전 관리     | Git/GitHub                     | docs/ 마크다운 문서 + 소스코드 관리     |

2.3 배포 구성

실 운영 배포는 범위에서 제외하며(요구사항 정의서 2.3절), 로컬 개발 환경 또는 단일 클라우드 인스턴스에서 Flask 개발 서버로 구동하는 시연 환경을 기준으로 한다. 더미 데이터로 초기화하는 시드(seed) 스크립트를 구현하여 재현 가능한 시연이 가능하도록 한다.

3\. 화면 설계

3.1 화면 목록

| **화면 ID** | **화면명**              | **설명**                                                | **관련 요구사항**   |
|-------------|-------------------------|---------------------------------------------------------|---------------------|
| SC-01       | 회원가입/로그인         | 개인/기업/기관 유형 선택 후 가입, 로그인 처리           | FR-01               |
| SC-02       | 마이페이지 대시보드     | 로그인 사용자의 신청 현황·검증서 요약 조회              | FR-01, FR-03, FR-04 |
| SC-03       | 가명·익명정보 처리 신청 | 더미 개인정보 입력 → 가명/익명 처리 규칙 적용 결과 확인 | FR-02               |
| SC-04       | CAVP 시험 신청          | 시험 대상 알고리즘 선택 및 시험 신청서 작성             | FR-03               |
| SC-05       | CAVP 시험 진행상태 조회 | 신청 목록 및 상태(접수/심사중/승인/반려) 조회           | FR-03               |
| SC-06       | 검증서 이력 조회        | 발급된 검증서 목록 및 상세 정보 조회                    | FR-04               |
| SC-07       | 검증서 위변조 탐지 결과 | 선택한 검증서의 무결성 점검 결과 표시                   | FR-05               |
| SC-08       | 관리자 대시보드 (Could) | 전체 신청/처리 현황 요약, 상태 변경                     | FR-06               |

3.2 주요 화면 상세

**SC-01. 회원가입/로그인**

- 구성요소: 유형 선택 탭(개인/기업/기관), 아이디·비밀번호 입력, 기업/기관 전용 추가 필드(사업자번호/기관코드)

- 정상 흐름: 필수값 입력 → 유효성 검사 통과 → 계정 생성 → 로그인 화면 리다이렉트

- 예외 흐름: 아이디 중복, 비밀번호 정책 미달, 필수 필드 누락 시 인라인 오류 메시지 표시

**SC-03. 가명·익명정보 처리 신청**

- 구성요소: 더미 개인정보 입력 폼(이름/생년월일/연락처), 처리방식 선택(가명/익명), 처리결과 미리보기

- 처리 로직: 가명 처리 시 대체 식별자(pseudonym_id) 발급 후 원본과 매핑 테이블에 분리 저장, 익명 처리 시 원본 식별정보를 저장하지 않고 통계적 대표값으로 치환

**SC-05 / SC-06. 조회 화면 공통 설계**

- 목록은 상태·기간 필터와 페이지네이션을 제공

- 행 클릭 시 상세 모달 또는 상세 페이지로 이동하여 이력·판정 근거를 표시

**SC-07. 검증서 위변조 탐지 결과**

- 모의 판정 로직: 저장된 검증서 해시값과 요청 시점 재계산 해시값을 비교하여 일치 여부를 '정상'/'위변조 의심'으로 표시(FR-05, 모의 로직)

4\. 데이터베이스 설계

4.1 ERD 개요

users(1) — personal_info(1:1), users(1) — cavp_applications(1:N), cavp_applications(1) — certificates(1:N) 관계로 구성한다. 모든 개인정보 성격의 컬럼은 가명·익명 처리 규칙이 적용된 값만 저장하며, 원본 식별정보는 저장하지 않는다(요구사항 정의서 5절 비기능 요구사항 - 보안).

4.2 테이블 정의

**users**

| **컬럼**      | **타입**                               | **설명**                               |
|---------------|----------------------------------------|----------------------------------------|
| id            | INTEGER PK                             | 사용자 고유 ID                         |
| username      | VARCHAR(50) UNIQUE                     | 로그인 아이디                          |
| password_hash | VARCHAR(255)                           | 비밀번호 해시                          |
| user_type     | ENUM(individual, company, institution) | 사용자 유형                            |
| org_code      | VARCHAR(50) NULL                       | 기업/기관 식별 코드 (개인 유형은 NULL) |
| created_at    | DATETIME                               | 가입일시                               |

**personal_info**

| **컬럼**             | **타입**                   | **설명**                          |
|----------------------|----------------------------|-----------------------------------|
| id                   | INTEGER PK                 | 레코드 ID                         |
| user_id              | INTEGER FK → users.id      | 소유 사용자                       |
| pseudonym_id         | VARCHAR(64)                | 가명 처리 시 발급되는 대체 식별자 |
| anonymization_level  | ENUM(pseudonym, anonymous) | 처리 방식                         |
| masked_display_value | VARCHAR(100)               | 화면 표시용 마스킹 값(더미)       |
| created_at           | DATETIME                   | 처리일시                          |

**cavp_applications**

| **컬럼**                  | **타입**                                       | **설명**                           |
|---------------------------|------------------------------------------------|------------------------------------|
| id                        | INTEGER PK                                     | 신청 ID                            |
| user_id                   | INTEGER FK → users.id                          | 신청자                             |
| algorithm_type            | VARCHAR(50)                                    | 시험 대상 암호 알고리즘(더미 목록) |
| status                    | ENUM(submitted, reviewing, approved, rejected) | 진행 상태                          |
| submitted_at / updated_at | DATETIME                                       | 신청/갱신 일시                     |

**certificates**

| **컬럼**       | **타입**                          | **설명**                        |
|----------------|-----------------------------------|---------------------------------|
| id             | INTEGER PK                        | 검증서 ID                       |
| application_id | INTEGER FK → cavp_applications.id | 발급 근거 신청 건               |
| cert_type      | ENUM(CAVP, KCMVP)                 | 검증서 종류(2종 Lifecycle 관리) |
| issued_at      | DATETIME                          | 발급일시                        |
| integrity_hash | VARCHAR(128)                      | 무결성 검증용 해시값            |
| tamper_status  | ENUM(normal, suspected)           | 위변조 탐지 결과(모의 판정)     |

7\. 예외 및 보안 설계

- 모든 입력 폼은 서버 사이드 유효성 검사를 적용하고, 실패 시 구체적 오류 코드를 반환한다.

- 비밀번호는 해시(예: bcrypt)로 저장하며 평문으로 저장하지 않는다.

- 개인정보는 실제 데이터가 아닌 더미 데이터만 사용하고, personal_info 테이블에는 가명·익명 처리된 값만 저장한다(요구사항 정의서 NFR-보안).

- 검증서 위변조 탐지는 저장 해시와 재계산 해시 비교라는 모의 로직으로 구현하며, 실제 암호모듈 수준의 서명 검증은 범위에서 제외한다.
