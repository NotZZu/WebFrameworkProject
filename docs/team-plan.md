## 2. 프로젝트 선정목적

공공기관 실제 RFP를 기반으로, 관심을 가져온 웹 서비스 테스트 자동화(Selenium) 역량을 실전 과제에 적용해보기 위해 본 과업을 선정함.

- **테스트 자동화 학습 목표**: Selenium 기반 웹 UI 테스트 자동화를 실제로 설계·구현
- **실제 공공기관 RFP 기반 실무 경험**: 요구분석·설계 실무 간접 경험
- **검증·테스트 중심 과업과의 적합성**: 원본 과업의 '6. 검수기준', '단위/연동 테스트' 항목과 방향이 일치

## 4. 프로젝트 목적

원본 과업의 핵심 요구사항을 축소된 웹 서비스로 구현하고, 그 서비스에 대한 Selenium 기반 웹 테스트 자동화 프레임워크를 구축하여 반복적인 회귀 테스트를 자동화한다.

1. **서비스 프로토타입 구현** — 가명·익명정보 전환, 검증서 관리·위변조 탐지 등 핵심 기능을 단순화한 웹 서비스로 구현
2. **테스트 자동화 체계 구축** — POM 기반 Selenium 테스트 프레임워크로 기능별 정상/비정상 시나리오를 자동 검증
3. **회귀 테스트 파이프라인 확보** — 기능 변경/버그 수정 시 자동 재실행되는 회귀 테스트 스위트와 결과 리포트 체계 마련

## 5. 주요 기능

### ① 축소 웹 서비스
- 사용자 계정 관리 및 로그인 (개인/기업/기관 유형 구분)
- 가명·익명 정보 처리 모의 기능 (더미 데이터 기반)
- CAVP 시험 신청 및 진행상태 조회 화면
- 검증서 발급 이력 조회 및 위변조 탐지 결과 표시

### ② Selenium 테스트 자동화 (핵심)
- POM 기반 테스트 자동화 프레임워크
- 기능별 정상/비정상 시나리오 테스트 케이스 설계
- 회귀 테스트 스위트 및 반복 실행 자동화
- 테스트 실행 결과 리포트 자동 생성(HTML)

> **범위 설계 원칙**: 1인 15주 프로젝트 특성상 서비스 기능은 시연 가능한 최소 수준으로 구현하고, Selenium 테스트 자동화 프레임워크에 개발 역량을 집중한다.

## 8. 기대효과

1. **Selenium 테스트 자동화 역량 확보** — POM 설계부터 테스트 스위트 운영까지 웹 테스트 자동화 전 과정을 경험
2. **수동 테스트 공수 절감** — 반복적인 회귀 테스트 자동화로 재검증 시간 단축, 회귀 오류 조기 발견
3. **공공기관 RFP 기반 실무 이해** — 요구분석·설계·검수기준 수립 실무 프로세스를 간접 경험
4. **재사용 가능한 테스트 자산 확보** — 구축한 자동화 프레임워크와 테스트 케이스를 이후 프로젝트/실무에 재사용
