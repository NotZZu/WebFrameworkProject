# 요구사항 정의서

**프로젝트**: 자동화 검증시스템 서비스 개선 및 확장 기능 개발 (Selenium 기반 웹 서비스 테스트 자동화 프레임워크 구축 중심 프로토타입)
**작성자**: 이상현 (학번 202647026) · **단계**: 분석(1~2주) · **버전**: v1.0 · **작성일**: 2026-09-12

## 1. 문서 개요

### 1.1 목적
본 문서는 「자동화 검증시스템 서비스 개선 및 확장 기능 개발」 과업지시서(발주기관: ETRI 부설 국가보안기술연구소)를 기반으로 한 웹프레임워크 교과목 팀별(1인) 프로젝트의 기능/비기능 요구사항을 정의한다. 개발계획상 분석 단계(1~2주)의 핵심 산출물로, 이후 설계·구현·테스트·안정화 단계의 판단 기준이 되는 문서로 활용한다.

### 1.2 문서 범위
원본 과업지시서의 요구사항 중 1인 15주 프로젝트로 시연 가능한 범위로 축소·재정의한 웹 서비스 프로토타입과, 본 프로젝트의 핵심 목표인 Selenium 기반 테스트 자동화 프레임워크에 대한 요구사항을 다룬다. 원본 과업의 실 운영 인프라, 실제 개인정보 연동, 실제 암호모듈 시험 로직 등 프로덕션 수준의 구현은 범위에서 제외한다.

### 1.4 용어 정의

| 용어 | 설명 |
|---|---|
| CAVP | Cryptographic Algorithm Validation Program. 암호 알고리즘 구현 적합성 시험 프로그램 |
| KCMVP | Korea Cryptographic Module Validation Program. 국내 암호모듈 검증 제도 |

| POM | Page Object Model. 웹 UI 요소를 페이지 단위 객체로 캡슐화하는 테스트 자동화 설계 패턴 |
| 회귀 테스트 | 기능 변경·버그 수정 후 기존 기능이 정상 동작하는지 반복 검증하는 테스트 |
| MoSCoW | 요구사항 우선순위 분류 기법: Must(필수) / Should(권장) / Could(선택) / Won't(제외) |

## 2. 프로젝트 개요

### 2.1 배경
발주기관은 2023년 11월부터 암호모듈(CAVP/KCMVP) 시험 온라인 서비스를 운영 중이며, 개인정보보호 강화(가명·익명정보 전환), CAVP 시험 자동화 범위 확장, 검증서 위변조 탐지, 기존 서비스 유지보수를 목표로 하는 확장 개발 과업을 발주하였다. 본 프로젝트는 이 과업지시서를 벤치마킹하여, 1인 학생이 15주 동안 수행 가능한 학습 프로젝트로 재구성한 것이다.

### 2.2 프로젝트 목표
- 원본 과업의 핵심 요구사항을 축소된 웹 서비스로 구현한다.
- 해당 웹 서비스에 대한 Selenium 기반 테스트 자동화 프레임워크를 설계·구현한다.
- 반복적인 회귀 테스트를 자동화하여 기능 변경 시 오류를 조기에 발견할 수 있는 체계를 마련한다.

### 2.3 프로젝트 범위

| 구분 | 포함 (In-Scope) | 제외 (Out-of-Scope) |
|---|---|---|
| 웹 서비스 | 로그인, 가명·익명처리 모의, CAVP 신청/조회, 검증서 이력/위변조 표시(더미 데이터 기반) | 실제 암호모듈 시험 로직, 실 개인정보 DB 연동, 운영 인프라 배포 |
| 테스트 자동화 | POM 구조, 정상/비정상 시나리오, 회귀 스위트, HTML 리포트 | 성능/부하 테스트 전문 도구 연동, 모바일·크로스브라우저 매트릭스 전수 테스트 |
| 문서화 | 요구사항 정의서, 설계서, 테스트 결과서, 매뉴얼 | 정식 감리·인증 심사 대응 문서 |

## 3. 이해관계자 및 사용자 유형

| 유형 | 설명 | 주요 니즈 |
|---|---|---|
| 개인 사용자 | 본인 명의로 시험/검증서 조회를 신청하는 일반 사용자 | 간편한 가입/로그인, 신청 현황 확인 |
| 기업 사용자 | 제품 단위로 CAVP 시험을 신청하는 기업 담당자 | 다건 신청 관리, 검증서 이력 조회 |
| 기관 사용자 | 정책·운영 목적으로 접근하는 기관 관계자 | 위변조 탐지 결과 확인, 통계성 조회 |
| 개발자(본인) | 웹 서비스 및 테스트 자동화 프레임워크를 설계·구현·검증하는 1인 개발자 | 재사용 가능한 테스트 자산, 신뢰도 높은 회귀 테스트 결과 |

| FR-02 | 가명·익명정보 처리 모의 | 더미 개인정보를 가명/익명 처리 규칙에 따라 변환하여 저장·조회한다. | Must | 가명·익명 정보 활용체계 전환 |
| FR-03 | CAVP 시험 신청/조회 | 사용자가 CAVP 시험을 신청하고 진행 상태를 조회할 수 있다. | Must | 향상된 CAVP 시험 및 자동화 범위 확장 |
| FR-04 | 검증서 이력 조회 | 발급된 검증서 목록과 상세 정보를 조회할 수 있다. | Should | 검증서 발급/관리 Lifecycle 관리 |
| FR-05 | 위변조 탐지 결과 표시 | 검증서의 위변조 여부 점검 결과를 화면에 표시한다(모의 판정 로직). | Should | 검증서 위변조 탐지 |
| FR-06 | 관리자 대시보드 | 신청/처리 현황을 요약하여 확인할 수 있는 관리자 화면을 제공한다. | Could | 서비스 개선 및 최적화 |

## 5. 비기능 요구사항 (Non-Functional Requirements)

| 분류 | 요구사항 | 우선순위 |
|---|---|---|
| 성능 | 주요 화면(목록/조회)은 더미 데이터 기준 2초 이내 응답한다. | Should |
| 신뢰성 | 회귀 테스트 스위트는 동일 조건에서 반복 실행 시 동일한 결과(Flaky 없음)를 보장한다. | Must |
| 유지보수성 | 테스트 코드는 POM 구조로 화면 변경 시 로케이터 수정만으로 대응 가능해야 한다. | Must |
| 사용성 | 웹 화면은 기본적인 반응형 레이아웃(PC 기준)을 지원한다. | Could |
| 보안 | 실제 개인정보는 사용하지 않으며, 더미 데이터에도 가명·익명 처리 로직을 동일하게 적용한다. | Must |
| 문서화 | 각 산출물(설계서, 테스트 케이스, 결과서)은 재사용 가능하도록 표준 양식으로 정리한다. | Should |

## 6. 제약사항 및 가정

- 본 프로젝트는 1인 팀으로 진행되며, 기획·설계·구현·테스트·문서화를 모두 동일인이 수행한다.
- 전체 개발 기간은 15주(1학기)로 제한되며, 원본 과업(4개월, 팀 단위)보다 축소된 범위로 재정의한다.
- 서비스 기능은 시연 가능한 최소 수준으로 구현하고, 개발 역량은 Selenium 기반 테스트 자동화 프레임워크에 집중한다.
- 개인정보는 실제 데이터가 아닌 더미 데이터를 사용하며, 실제 서비스 배포 및 운영은 범위에 포함하지 않는다.
- 사용 기술 스택은 분석 단계에서 확정하며(예: Python, Selenium, Flask 등), 변경 시 본 문서를 갱신한다.

## 7. 우선순위 매트릭스 (MoSCoW)

| 우선순위 | 정의 | 해당 요구사항 |
|---|---|---|
| Must | 반드시 구현해야 하는 핵심 요구사항 | FR-01, FR-02, FR-03, FR-10, FR-11, FR-12, NFR-신뢰성, NFR-유지보수성, NFR-보안 |
| Should | 가능하면 구현하되, 일정상 후순위로 조정 가능한 요구사항 | FR-04, FR-05, FR-13, FR-14, NFR-성능, NFR-문서화 |
| Could | 여유가 있을 때 구현하는 선택 요구사항 | FR-06, FR-15, NFR-사용성 |
| Won't | 본 프로젝트 범위에서 제외하는 요구사항 | 실 운영 배포, 실 개인정보 연동, 성능/부하 전문 테스트, 정식 감리 대응 |
