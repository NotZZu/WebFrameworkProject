# 설계 변경 이력 (v1.1 이후)

시스템 설계서 v1.1을 기준으로, 이후 구현 과정에서 바뀐 설계 사항을 기록한다. 설계서 본문(상태 값, 화면 설명, API 목록)에는 아래 1~3번이 반영되어 있다.

| 번호 | 변경 | 내용 | 관련 시험 |
|---|---|---|---|
| 1 | 신청 상태 '취소' 추가 | `cavp_applications.status`에 `cancelled` 추가. 신청 본인만 접수 대기(submitted) 상태에서 취소할 수 있고, 취소하면 진행 중 잠금이 풀려 같은 알고리즘을 다시 신청할 수 있다. 기관의 상태 변경(PATCH)으로는 취소할 수 없다. | UT-CAVP-21~27, IT-46~50, ST-08 계열 |
| 2 | API 추가 | `POST /api/cavp/applications/{id}/cancel` (본인 전용, 200/403/404/409) | IT-46~49 |
| 3 | SC-08 관리자 대시보드 구현 | `GET /api/admin/summary`(기관 전용)와 `/admin` 화면. 전체 신청의 상태별·알고리즘별 건수, 심사 대기, 최근 7일 신청, 위변조 의심 검증서, 최근 신청 5건, 주의 사항을 보여 준다. 개인·기업 계정은 API 403, 화면은 대시보드로 이동. | UT-ADM-01~11, IT-51~54, ST-09 계열 |
| 4 | 보안 정책(CSP) 확대 | 화면의 인라인 스크립트를 `app/static/js/*.js`로 분리하고 `script-src 'self'`를 적용했다. 이전에는 `frame-ancestors 'none'`만 적용했다. 스타일은 인라인을 허용한다(`style-src 'self' 'unsafe-inline'`). | IT-55, ST-10 |
| 5 | 상태 변경 실패 처리(DF-17) | 실패 시 상세와 목록을 먼저 다시 불러온 뒤 오류 안내를 표시한다. | ST-05-N6 |

## 시험 문서와의 관계

- 시험계획서(`testplan.docx`)는 특정 시점의 단위시험 케이스 표를 담은 문서다. 위 변경 이후 추가된 케이스는 시험 진척도 대시보드(`assets/tracker`)가 자동 생성하는 목록이 최신이다.
- 요구사항 정의서의 우선순위(FR-06 Could)는 그대로 두고, 구현 여부만 이 문서에 기록한다.
